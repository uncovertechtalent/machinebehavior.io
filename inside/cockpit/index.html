    What the cockpit is

    The cockpit is the local app in which Stefan Coetzee runs his work. Every task, finding, and decision is an item in a local issue tracker, with one label for its area and one for its kind. The app shows the items by area, with a scorecard for each area and the trend. It runs on his own machine, and its data stays there.

    This page is the public view of the same structure. The snapshot holds counts per area and the open pull requests and issues in public repositories, and nothing else: no item text, no item numbers from the tracker, and no names. Work outside the eight areas is not in it.

    The CTO powersuit is a set of agent skills, one module per CTO function from the deploy gate to the hand-over, that one person uses to run a company's whole engineering platform. The cockpit is that person's view of the work. A company version with the same structure is planned: the plugins' read-only audits write their findings into the areas, and the scorecard shows what is open in each part of the CTO job.

    • Mission Control: the live operations view, with the gate and deploy state of the three sites.
    • Board: the work items of this site, from GitHub Issues.
    • CTO powersuit: the plugins by area, with install commands for the latest release.

    Cockpit · data: the snapshot, written by the cockpit's export and published with a pull request. The build checks it against the contract and writes this page; the deploy gate runs the same check. How it works: Cockpit page. Decision record: ADR-0031.
