    Conformity gate

    owner Stefan Coetzeecreated 2026-10-09updated 2026-10-25reviewed 2026-10-09review by 2027-01-073 min readreference

    The conformity gate is a set of mechanical checks run by .github/actions/conformity/run.py against every published page. A blocking failure stops the deploy; the previous build stays live. Results are rendered at /conformity/ (self-assessment, not a certification) and stored in conformity/latest.json. The requirements under test come from the working draft published at /conformity/standard/ (ADR-0019).

    In our words, the gate is a control function that runs at the speed of change. In the terms of McKinsey's AI operating system, it manages "continuously, not through checkpoints", and its findings are the "signals, thresholds, and exceptions" a person acts on, in place of a yearly audit. The standard behind it is Continuous Conformity.

    Blocking checks

    CheckFails when
    rules.blockingA page hits a rule in the blocking tier of the vendored rule table (service-closer, filler-idiom, hook-opener)
    placeholdersA page carries placeholder text; the patterns are in site-tier.json under placeholder_pattern
    predictions.hashesA file in predictions/ differs from the sha256 in predictions/HASHES.txt
    site.consistencyA page is missing from sitemap.xml, has no canonical link, or links internally with a relative or .html path
    page.labelA page says self-assessment near the top without the words "not a certification"
    componentsThe vendored rule table differs from the sha256 recorded in the site configuration
    actions.pinnedA workflow or composite action under .github/ references an outside action by tag, branch or short SHA, or a Docker image by tag; a commit SHA cannot be moved to other code
    actions.ownersAn outside action, reusable workflow or Docker image comes from an owner outside actions_owners_allow in site-tier.json; a pinned commit from a lookalike repository still passes actions.pinned

    Local check (dry run only)

    CheckFails when
    private.termsA tracked file, a file name or a published file of the build output carries a term from the owner's private term list: names of prospective employers or clients, internal shorthand, family names in business copy, private hosts and addresses

    The term list stays on the owner's machine, outside every repository, so this check runs only in a dry run with --private-terms <file>, never in CI, and never appears on /conformity/. A pushed commit is public before CI runs; the owner's pre-push hook from the CTO powersuit (security.private-terms) is what stops a term before it leaves the machine. Hits show the file, the line and the term's label, never the term. Intended mentions go into .private-terms-allow at the repository root: a path glob, a label, and a reason. The matcher runs on every CI run against made-up terms in fixtures-private-terms.jsonl, through grader.fixtures.

    Warnings (never block)

    • praise-opener rule hits.
    • A page missing from llms.txt.
    • Freshness: pages whose newest date is older than 90 days, or with no date.

    Exemptions from the rule scan

    Code, blockquotes, <q>, spans with class mono and text inside double quotes. Quote a phrase to discuss it; the scan skips it.

    Records

    • Run records: workflow artifacts, kept 90 days.
    • History and open findings: conformity/latest.json in git, kept indefinitely. A finding closes only when a later run passes.

    Ownership and false positives

    The legislation-track session owns the gate; Stefan Coetzee decides tier changes. A false positive is never fixed by editing the rule table in the site repository. Record the page, line and rule with the owner; rewriting the sentence unblocks the deploy in the meantime. See Gate blocked a deploy.

    Sites that share the gate

    tychat.io and uncovertechtalent.com run this gate pinned to a commit of main. A change to .github/actions/conformity/, an engine fix included, reaches them only when the gate owner bumps that commit in both repositories. Dependabot does not propose the bump, because this repository has no release tags. The bump step is in conformity/README.md.
