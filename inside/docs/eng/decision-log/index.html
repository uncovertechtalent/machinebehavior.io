    Decision records

    owner Stefan Coetzeecreated 2026-10-26updated 2026-10-26reviewed 2026-10-09review by 2027-01-073 min readreference

    Each record states one decision: its number, date and status, the context that forced it, the decision, and what it costs. Decisions are made by Stefan Coetzee unless the record says otherwise. A record is never deleted: when a later decision replaces it, its status becomes superseded and it links the record that replaced it.

    Add a record

    1. Copy the newest record in scripts/docs/eng/ to adr-NNNN-short-name.md with the next number.
    2. Fill in context, decision and consequences; set status.
    3. If it replaces an earlier record, add supersedes: here and superseded_by: there, and set the old one to superseded. The build stops when the two sides disagree. If it replaces only part of an earlier record, write that in a sentence in both records (Replaced by ADR-NNNN for ... in the old one, with a link to the new record, and This replaces the ... paragraph of ADR-NNNN in the new one) and leave the old record accepted.
    4. Run the docs build, the gate dry run, and push. The change also appears in the changelog.

    Child pages

    • ADR-0001: Root-absolute links onlyInternal links are root-absolute directory URLs (`/man/`, `/style.css`), never relative and never ending in `.html`.
    • ADR-0002: The deploy is gatedGitHub Pages deploys from GitHub Actions, and the deploy job depends on the conformity job.
    • ADR-0003: The map loads d3 and its fonts from public CDNsThe map page loaded d3 7.9.0 from cdnjs and Space Grotesk and JetBrains Mono from Google Fonts.
    • ADR-0004: The map refresh keeps the larger snapshotThe deploy job replaces `map/graph.json` only when the new crawl has at least as many nodes and links as the committed snapshot.
    • ADR-0005: Deploys feed Grafana without changing the workflowsA separate exporter polls the GitHub Actions API and writes runs, steps and gate checks to Loki and Prometheus.
    • ADR-0006: Inside reads the deploy feed from the GitHub API in the browserThe page called the GitHub Actions API from the visitor's browser for each repository on every load.
    • ADR-0007: Docs search over its own index, Enter opens the first hitThe docs top bar searched `inside/docs/search.json` only, and Enter opened the first hit.
    • ADR-0008: Docs pages are map nodesDocs pages carry their front matter as meta tags, and the crawler adds them to the graph with parent links as `tree` edges.
    • ADR-0009: Publish vault notes with a review labelThe SRE folder and 28 standards clusters are published as docs spaces, with private addresses, e-mail addresses and the former employer's name redacted, and a label on every page saying it has not been reviewed against its source.
    • ADR-0010: No third-party requests on page loadFonts and d3 are served from the site itself, and the Inside deploy feed is a JSON written by the deploy job.
    • ADR-0011: A public ticket board from GitHub IssuesWork items are GitHub Issues on the public repository, shown on [the board](/inside/board/).
    • ADR-0012: One top bar and one search index for InsideEvery Inside page carries one top bar, written by `bar()` in `scripts/inside_chrome.py`.
    • ADR-0013: A service catalog from YAML in the repositoryEvery service is one YAML file in `services/`, validated at build by a strict standard-library reader.
    • ADR-0014: A status page from records the site already publishes`/inside/status/` reads each site's gate record, `/inside/deploys.json` and the map snapshot time in the browser, and shows the incident history from `incidents/*.yml` with the stages Investigating, Identified, Monitoring and Resolved.
    • ADR-0015: Owner and review dates on every docs pageDocs front matter gains `owner`, `reviewed`, `review_by` and `type` (Diátaxis).
    • ADR-0016: A public-demo banner and a stated access modelEvery Inside page except the map carries a banner saying the intranet is a public demo and that in production it sits behind single sign-on.
    • ADR-0017: State the on-call model and propose Alertmanager routingThe [On-call and escalation](doc:obs/on-call) page states the model as it runs: one operator, agent sessions as responders, the deploy gate as the only control that acts on its own, and no Alertmanager.
    • ADR-0018: Numbered decision records and a generated changelogEach decision is a numbered record (ADR-0001 onward) with a status (proposed, accepted, superseded), context, decision and consequences, one docs page each.
    • ADR-0019: Publish the definition draft before the committee routeThe working draft "Continuous Conformity for Deployed AI Systems" (0.3, 36 requirements) is public as a reference at /continuous-conformity/ before any standards committee has seen it, reversing the committee-first order of 2026-10-04.
    • ADR-0020: A five-minute founder tour on one pageOne page at /inside/tour/ walks a founder through the platform in six stops, each with a screenshot of the live page, what to notice, what it does in a company, and the link.
    • ADR-0021: One navigation source for the whole sitesite/nav.yml defines the sections and pages once; scripts/site_chrome.py writes the top bar, breadcrumbs, sidebar and footer of every page between markers and checks the sitemap and llms.txt against the tree.
    • ADR-0022: Section sidebars from the navigation sourceResearch and Inside pages carry a sidebar with every page of their section, written from site/nav.yml; a column beside the content from 1100 px, a closed disclosure above it on narrower screens.
    • ADR-0023: Topic hubs across research, docs, posts and ticketsSeven topic hubs at /topics/<key>/ list every research page, Inside page, docs page, post and board issue on one subject; site/topics.yml holds the rules, and a Topics block in each sidebar marks the topics of the current page.
    • ADR-0024: SRE principles tied to the running platformFourteen hand-written principle pages in the SRE Handbook space link each principle to the services, records and docs that apply it, with a state per page; services name their principles in YAML, and the vault import keeps hand-written pages.
    • ADR-0025: One design system, two layouts, light and dark from the system settingOne token file for colour, type and spacing, component CSS for the chrome and the shared components, a reading layout and an app layout under one brand, light and dark from prefers-color-scheme with nothing stored on the device. (Dark scheme replaced by ADR-0042.)
    • ADR-0026: Mission Control, the live operations view inside the portalOne screen at /inside/mission-control/ shows the gate and deploy state of the three sites, the deploy feed, open incidents, this site's gate result and the public Grafana dashboards as tabs that load on a click, with a slot for the internal AWS spend panel.
    • ADR-0027: Structured data on every page from the navigation sourceEvery page carries one JSON-LD graph written by the chrome, for entity understanding (no claim that it drives AI citations): Stefan Coetzee as Person and author, the site as WebSite with its search, the page as Article, TechArticle, CollectionPage or WebPage with its dates, a BreadcrumbList, and DefinedTermSet on the two pages that define terms. The build fails on invalid JSON-LD.
    • ADR-0028: The home page as the front page of the portalThe home page leads into the sections of the portal: a hero with the map, cards for Research, Inside, Mission Control, Docs, Topics and Map, the latest research and the topics, written from site/nav.yml; the case-file list that repeated the claims is gone.
    • ADR-0029: Changes reach main through pull requestsEvery change to main goes through a pull request whose Conformity checks pass, enforced by a branch ruleset on main; the merge is the review step; the gate bot and the probe record push through deploy keys.
    • ADR-0030: The CTO powersuit pages are built from the pinned release/cto-powersuit/ and one page per plugin are built by scripts/build_powersuit.py from the powersuit repository at a release tag and commit pinned in site/powersuit.yml; the pages carry a sidebar of the plugins by area in place of the section sidebar, and CSS scoped to them.
    • ADR-0031: The cockpit page is built from the public GitHub Issues of the owner's repositories/inside/cockpit/ shows the issues and pull requests of the owner's public repositories by area of the CTO job, written by scripts/build_cockpit.py at each deploy from the GitHub API; a contract check in the build and in the Conformity checks job lets only public GitHub data reach the page.
    • ADR-0032: The masthead is built from a public seats file/inside/masthead/ shows the seats of the house, the holder of each, the machinery that runs its staff work, and the gates that apply with where each one runs, written by scripts/build_masthead.py from inside/masthead/seats.json; a contract check in the required job refuses a file outside the contract; the house name sits in one field; the product of the seats is called the C-suit.
    • ADR-0033: The site moves to S3 and CloudFront, built with Terraform, and deploys there next to GitHub Pages until the cutoverEvery push to main that passes the gate also syncs the same build to a private S3 bucket behind CloudFront, through a GitHub OIDC role that may write one bucket and invalidate one distribution; the infrastructure is the public Terraform repository site-infra, and GitHub Pages stays deployed as the rollback until the apex has run on CloudFront without one.
    • ADR-0034: Inside gets a light intranet theme of the design system, and its landing page a tab per seatA page that sets data-mb-theme="intranet" on its html element gets light intranet tokens (white panels on light grey, one blue accent) in both system settings; the Inside landing page opts in first and shows the three site cards, then one card per seat as tabs, then the selected seat's dashboard from seats.json and cockpit.json, written by scripts/build_inside_seats.py and checked in the required job.
    • ADR-0035: Every page under /inside/ uses the intranet theme, set by the site chromeThe site chrome sets data-mb-theme="intranet" on the html element of every page under /inside/ (Inside, its services, and Docs) and removes it from every other page, so the light intranet theme of ADR-0034 covers all of Inside, new pages get it with no step of their own, and site_chrome.py --check holds it in the required job.
    • ADR-0036: The Inside seat cards become folder tabs joined to the dashboard panelThe seat cards on the Inside landing page become compact folder tabs that carry only the seat code and one status pill (blocked beats open beats clear), with the areas and the counts moved into the dashboard panel below; the selected tab is white, taller and blue-outlined, and overlaps the panel's top border so the tab and the panel read as one outline. Six tabs stay on one row at every width, a phone shows PUB for the publisher and the count alone on each pill, the theme tokens of ADR-0034 give every colour, and the tab controller moves to inside/seat-tabs.js with its own test.
    • ADR-0037: A pager on Discord with a rotation, the board for every alert, and an outside heartbeatOne Alertmanager serves both Prometheus servers in the house. A page becomes an incident in a PagerDuty-style pager on a private Discord server, with Acknowledge, Resolve and Escalate buttons, a rotation and an escalation policy in pager/rotation.yml, and a read-only responder agent as its second layer. Every page and ticket also opens an issue on the board, which keeps the page's redacted record; the on-call pages show the rotation, the last pages and the pager load from a public snapshot. An always-firing Watchdog per Prometheus pings a heartbeat check outside the house.
    • ADR-0038: URL taxonomy and redirectsThe site adopts a small set of top-level pillars (Research, Conformity, Inside, Docs) with the CTO page as the action, nests the flat root registers and reference under their pillar, consolidates the three conformity routes under one /conformity/ hub, and freezes the URLs that carry external or legal weight. Moved URLs redirect two ways from one source, site/redirects.yml: a CloudFront 301 at the edge and a GitHub Pages stub with a canonical link. The decision is accepted; the moves land in phases 1 to 3.
    • ADR-0039: The research section uses a report theme, set by the site chromeEvery page under /research/ gets data-mb-theme="report": a fixed light theme in the register of a consulting report, with Newsreader 300 headlines over an Inter body, the title on a dark teal band, hairline tables, and captioned tables numbered as exhibits with a source line where the data is published. The chrome sets it by URL, as ADR-0035 does for Inside.
    • ADR-0040: Report pages carry the furniture of a consulting reportThe research section's report pages take over the evidence motifs of consulting articles: exhibits numbered in the HTML with a finding as the title, a Note line beside the Source line, references to exhibits in the text, At a glance at the top, sidebar boxes, a page-type pill, the reading time and a print stylesheet. Engagement furniture (share rails, stock hero art, AI summary buttons, ratings) stays out.
    • ADR-0041: The front page uses the report theme, with one message and one lead findingThe front page takes the report theme of ADR-0039 and the layout of a consulting home page: a title band with the second-brain graph, the programme's finding, a lead finding with its number chosen by hand, research rows and doors written by build_fallbacks.py from site/nav.yml and the research pages, two Use it cards, and where it aims. The long explanatory paragraph moves to the research index.
    • ADR-0042: The site has one light colour schemeThe dark values that followed the visitor's system setting are removed from design/tokens.css, color-scheme becomes light, and the second-brain map draws its light palette only (its canvas is dark again under ADR-0043). The top bar and the report theme's title band stay dark as chrome. The /conformity/ page, written by the shared gate action, keeps its own dark block until that action changes.
    • ADR-0043: The second-brain map draws its graph on a dark canvasThe map's canvas, and only the canvas, is dark in every setting: the top bar's colour from --mb-bar-bg, with the bright node colours and light labels it used before ADR-0042. The panel, the hover tip and the preview sheet stay light, the legend dots get an outline so the bright colours hold on the light panel, and the stamp on the canvas uses the bar's text colours.
