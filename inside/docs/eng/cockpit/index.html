    Cockpit page

    owner Stefan Coetzeecreated 2026-10-14updated 2026-10-14reviewed 2026-10-14review by 2027-01-123 min readhow-to

    The cockpit page shows Stefan Coetzee's work in the eight areas of the CTO job as counts: per area, the open, in progress, blocked, and recently closed items, the open items by kind, and the age of the oldest; for all areas, the totals and a 14-day trend; and the open pull requests and issues in public repositories. The cockpit itself is a local app, and its data stays on his machine. The page gets one file from it, the snapshot, through a pull request. Decision record: ADR-0031.

    Files

    FileWhat it is
    inside/cockpit/snapshot.jsonThe published snapshot, served at /inside/cockpit/snapshot.json
    inside/cockpit/index.htmlThe page; the build writes the blocks between <!-- static:cockpit-* --> markers, the rest is written by hand
    inside/cockpit/cockpit.cssThe page's styles, from the design tokens
    scripts/build_cockpit.pyThe contract check and the build
    scripts/test_build_cockpit.pyTests of the check and the blocks, run in the Script tests job
    scripts/fixtures/cockpit-snapshot.jsonThe sample snapshot (source fixture) the tests start from

    The snapshot contract (schema 1)

    KeyAllowed
    schema1
    generatedA UTC timestamp, 2026-10-14T14:00:00Z
    sourcebeads-desk@<commit>, or fixture for the sample file; the page labels a fixture as sample figures
    areasThe eight areas, each once: key and name from a fixed list (direction Direction, delivery Delivery, operations Operations, money Money, security Security, ai AI, people People, knowledge Knowledge), and the counts open, in_progress, blocked, closed_7d, findings_open, decisions_open, actions_open, oldest_open_days
    totalsopen, in_progress, blocked, closed_7d, each the sum over the eight areas
    trendDays in date order, each with date, open (items not closed by the close of that day), and closed (closed that day); the page shows the last 14
    public_itemsUp to 200 items with repo, kind (pr or issue), title, url, and state (open, closed, or merged); the page lists the open ones

    Every count is an integer from 0. A key outside the table, a key that appears twice in one object, a missing key, or a value of another form fails the check. The title of a public item is the only free text: at most 300 characters, no control characters, no < or >. An item's owner must be on PUBLIC_OWNERS in scripts/build_cockpit.py (now uncovertechtalent), and its URL must be https://github.com/<repo>/pull/<n> for a pull request or .../issues/<n> for an issue.

    The cockpit's exporter refuses to write a file that breaks the same contract. The check here does not trust that: it runs again wherever the file is used.

    Where the check runs

    • python3 scripts/build_cockpit.py checks the snapshot before it writes the page, and stops on any violation.
    • python3 scripts/build_cockpit.py --check runs as the step "Cockpit snapshot matches the contract and the page" in the Conformity checks job, before the gate. That job is the required check on pull requests, and the deploy waits for it. The step also fails when the page's blocks or its sitemap date differ from the snapshot.
    • python3 scripts/test_build_cockpit.py runs in the Script tests job.

    Publish a new snapshot

    1. On the machine that runs the cockpit: python3 -m beads_desk export --public-json FILE.
    2. In a clone of this repository, on a branch from origin/main: python3 scripts/build_cockpit.py --snapshot FILE. It checks the file, copies it to inside/cockpit/snapshot.json, writes the page blocks, and sets the page's sitemap date to the snapshot's date.
    3. Read the diff: counts, dates, and the public items, nothing else.
    4. Run the gate dry run, then open a pull request titled ADR-0031 Cockpit snapshot <date> (ADR-0029).

    Later: a scheduled export

    Not built. The machine that runs the cockpit exports on a timer and pushes the snapshot to a branch with a deploy key of its own, which can write branches only; the machine account opens the pull request, and the contract check in CI stays the gate. Until then, a snapshot is published by hand as above.
