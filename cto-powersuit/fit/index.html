    fit

    Where the company stands, and the big technical decisions.

    The entry assessment: runs the sdlc audit and recommends which modules to fit and in which order. Its repo clinic audits a public repository at its owner's request, and its file-findings skill files a review's findings as GitHub Issues labelled by area, kind, and severity, with a scorecard per area.

    • Version 0.3.1
    • 3 skills
    • 1 gate check
    • Running on this site: Inside

    What it does

    The fitting plan for an existing estate. /fit:estate-assessment reads a repository and its docs, runs the sdlc audit, and recommends for every module of the suit whether to fit it now, later or not at all, in an order that respects the dependencies between modules. The result is one page, docs/fit.md, with a reason, a first step and an owner per module.

    /fit:repo-clinic is the same look from the outside, for a public repository whose owner asked for feedback. It runs the sdlc audit, the supply-chain and secrets checks of the security module and a provenance read, and drafts one short report with the top three gaps and one small pull request plan with its patch. Secrets and security holes go to a private note. It writes to a clinic folder outside any public repository and never posts, forks, pushes, or opens a pull request.

    Modules depend on each other. The gate comes before the module checks, because those checks run in it. The docs tree comes before the handover, because the new owners train on its runbooks. Observability comes before SLOs. A module fitted before its dependencies has no gate to run its check in, no runbooks to train on or no metrics to measure. The assessment writes the order down.

    Install

    Add the marketplace at release v0.4.0 once, then install the plugin and restart Claude Code.

    claude plugin marketplace add uncovertechtalent/cto-powersuit#v0.4.0
claude plugin install fit@cto-powersuit

    Skills

    • /fit:estate-assessment

      Assess a repository and its docs, build on the ranked gap list of the sdlc audit, and recommend which modules of the suit to fit, in which order and why, with the first skill, the effort class, the dependencies and an owner per module, written to docs/fit.md.

    • /fit:file-findings

      File the findings of a CTO review as GitHub Issues in the company's own repository, labelled by area (area:direction to area:knowledge), kind (kind:finding, kind:decision, kind:action) and severity, and write one scorecard per area with the checks run, the findings by severity, and a one-line verdict.

    • /fit:repo-clinic

      Audit a public repository at its owner's request and draft one short public report with the top three gaps, one small pull request plan with its patch prepared, and a private note for any secret or security hole.

    Source

    The CTO powersuit is a set of agent skills, one module per CTO function from the deploy gate to the hand-over, that one person uses to run a company's whole engineering platform. fit is one of its 19 plugins, published by Stefan Coetzee.

    The skills, templates, checks, fixtures, and the full README of fit at release v0.4.0: github.com/uncovertechtalent/cto-powersuit/tree/v0.4.0/plugins/fit. License: MIT. Every plugin of the powersuit: CTO powersuit.
