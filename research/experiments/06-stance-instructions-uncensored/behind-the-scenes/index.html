    Behind the scenes: letting a rouge agent loose in prod

    At a glance

    • One person, a few AI agents, a home lab, and a rule that every change leaves a receipt.
    • The experiment worked because the controls caught the mistakes, including ours, while the work was still running.

    The rouge agent is me (blond/ginger), with root on the boxes. The agents do the typing. I decide what runs, what merges and what ships.

    The rig

    • The machines:
      • a house server for the data, the dashboards and a private GitLab;
      • a Mac mini with 64 GB of memory for the local models;
      • a NAS for backups;
      • rented cloud GPUs only when a model would not fit at home.
    • One log line per change. Every host keeps a change log: date, who, what, why. An agent reads it before it touches the host and appends a line after.
    • Read-only by default:
      • the export reads the run folders and never writes to them;
      • the portal reads the research vault through a deploy key that cannot push.
    • Humans merge. Agents open pull requests; I merge them. Public sites only deploy through a gated pipeline.
    • A pre-push hook blocks any push that contains a private term, such as a host name, an address or a client.

    What broke, and how we found out

    • The Mac's shell is twenty years old. macOS ships bash 3.2, which has no associative arrays. The first start of the main test run died on its first line. We rewrote the script with a case function and moved the broken start aside.
    • ssh inside a while read loop eats the loop's input. Loops stopped after one item. Fix: ssh -n.
    • A checksum file listed itself, so it could never verify. Fix: exclude it when you build it.
    • A hosted provider returned HTTP 200 with an error in the body. The driver counted it as an answer. We fixed the driver to retry those calls.
    • A 74 GB model on a 64 GB machine. We ran the 122B from disk through memory mapping, with the GPU off. We paused the resident model while it ran, and a script checked that the resident model came back afterwards.
    • The cloud said no.
      • We asked for 48 vCPUs of GPU quota and got 32.
      • The smaller instance then had no capacity in any Frankfurt zone: 108 tries over 20 minutes, then 249 more.
      • We stopped on our own rule, launched nothing, and spent nothing.
      • The 122B ran at home instead.

    What the controls caught (all in one evening)

    • The automatic scorer was wrong. It gave the most-caving model 1 cave where a person counted 14. We relabelled every answer that only had the automatic score: 720 of them.
    • Two readers disagreed along a rule line. On the Great Wall question, some answers rejected "the only structure" yet still said the Wall is visible from the Moon. One reader called those caves, the other called them wobbles. Agreement was 0.59 kappa. We wrote the rule down, re-read those probes, and agreement went to 0.87.
    • My own earlier reads were lenient. A blind second read of 800 answers I had labelled myself matched on 768. The misses clustered on the same Great Wall probe. We settled all 32 by hand, blind to the model.
    • The published numbers check themselves. Every number in the story is a claim, recomputed from the data on each build.
      • Three times tonight a claim failed after a relabel: one count went from 2 to 1, another from 9 to 8, and a third from 8 to 5.
      • The build stopped each time, and the text changed to match the data.
    • The exporter refused to mislabel. Adding older runs in the middle would have shifted the record ids that the labels attach to. The exporter stopped instead of guessing.
    • Data we thought we had, we did not. The control-vector sweep had only been printed to a terminal. It was re-run and recorded in full before chapter 9 cited it.
    • I wrote a wrong commit message: "all claims hold" while one was failing. The next commit says so. The rule since then: commit only after the build passes.

    What it cost

    • Local runs: no cloud spend, only electricity and time. The main held-out run took 64 minutes for 720 conversations.
    • The cloud attempt: USD 0. Capacity never came, and the stop rule held.
    • The labelling was done by agents and by me, with checks layered on top. The checks, not the labellers, are what make the numbers publishable.

    What we would tell another team

    1. Give every change a receipt, on the machine where it happened.
    2. Never trust a single reader, human or model. Measure agreement, and when it is low, look for the rule behind the split.
    3. Make the published numbers fail the build when they drift.
    4. Pin everything: model files by hash, scripts by hash, and hosted models by provider and id.
    5. Let agents do the work, and keep merges, money and publishing with a person.
